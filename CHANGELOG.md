## [0.2.0] - 2026-10-18

### Added

- Hosted CI for the browser, memory and MongoDB suites and the scanners ([ADR-48](docs/decisions.md#adr-48-hosted-ci-runs-the-browser-memory-and-mongodb-suites-and-the-scanners), [docs/quality.md](docs/quality.md#hosted-ci), [docs/e2e.md](docs/e2e.md#hosted-ci)): `.github/workflows/ci-e2e.yml` (the end-to-end suite in five shard jobs on the Chrome of the runner image, and `make e2e-mongo` against a `mongo:8` service container pinned by digest on `127.0.0.1:27117`), `.github/workflows/ci-security.yml` (Semgrep and Trivy, SARIF kept as artifacts), a `memory-test` job in `ci.yml` (`make memray`) and `.github/workflows/mutation.yml` (mutation testing, started by hand only, no schedule). A local action, `.github/actions/no-skipped-tests`, applies the hook rule to every hosted test job: a skipped test, an empty report or a cut-off report fails the job. The JUnit file of the unit job moved to `reports/junit/cov.xml`. Nothing requires any job to pass; Qodana, the replica-set suite and the hooks stay local. The new workflows have not run yet, so no hosted figure is recorded.
- ClusterFuzzLite fuzzing ([ADR-47](docs/decisions.md#adr-47-fuzzing-runs-in-clusterfuzzlite-from-testsfuzz), [docs/fuzzing.md](docs/fuzzing.md)): Atheris targets in `tests/fuzz` for the text source parsers, the JSON stream reader, the rewriter, the MongoDB filter, pipeline and URI guards, the name validators and the number formatter, with seeds and dictionaries; `.clusterfuzzlite/` (a Python 3.14 image, hash-pinned tools); `cflite_pr.yml` (7 minutes on a pull request) and `cflite_batch.yml` (nightly, with a corpus prune). A smoke test runs the targets in the unit suite. Dependabot reads the image files (security updates only); `.trivyignore` has `AVD-DS-0002` for the image's root user.
- Tests for the split of the two files, the migration of an old `settings.json`, every way `credentials.json` can be missing, broken, unreadable or loose, the `.corrupt-<n>` pair, the two size caps and a live-server flow that replaces the file by hand.
- Policy documents: [docs/roadmap.md](docs/roadmap.md) (the software is complete; maintenance only; feature pull requests welcome except SQL database support), [docs/dependencies.md](docs/dependencies.md) (how dependencies are chosen, obtained, scanned and updated, with the limits of Trivy and Dependabot), [docs/secrets.md](docs/secrets.md) (the project's secrets and the leak procedure) and [docs/assurance-case.md](docs/assurance-case.md) (threat model, controls, tests and residual risks).
- [docs/release.md](docs/release.md#verifying-a-release) and the README explain how to verify the Sigstore attestation of a PyPI file with `pypi-attestations`.
- `.github/workflows/trivy-weekly.yml`: the project's Trivy scan (same `trivy.yaml`, pinned image and `scripts/trivy.sh` as `make trivy`) every Monday and on demand, so the dependencies are checked between pushes; a fixed HIGH or CRITICAL finding fails the run. GitHub stops scheduled workflows after 60 days without repository activity ([ADR-40](docs/decisions.md#adr-40-a-weekly-trivy-scan-and-the-openssf-scorecard-run-in-github-actions), [docs/dependencies.md](docs/dependencies.md#weekly-trivy-job)).
- `.github/workflows/ci.yml`: a hosted job that runs `make lint typecheck caps cov` on every push to `main` and every pull request, and uploads a JUnit and coverage report. Nothing requires it to pass ([ADR-44](docs/decisions.md#adr-44-a-hosted-ci-job-runs-the-unit-tests)).
- `.github/workflows/codeql.yml` (CodeQL for Python, JavaScript and the workflow files, on pushes to `main` and weekly) and a ruleset "main: no deletion, no force-push" on the default branch ([ADR-43](docs/decisions.md#adr-43-codeql-a-ruleset-on-main-and-signed-release-assets)). Neither requires reviews or checks, so direct pushes keep working.
- [docs/release.md](docs/release.md#rebuilding-a-release): the 0.1.0 wheel and sdist were rebuilt from the tag on another machine and are byte-identical to the PyPI files.
- The v0.1.0 release page carries the wheel and the sdist as on PyPI and their Sigstore bundles; the procedure is in [docs/release.md](docs/release.md#release-assets) and the release rule in `CLAUDE.md` and `AGENTS.md` now includes it.
- A ruleset "v* tags: no deletion, no update, no force-push" protects release tags ([ADR-43](docs/decisions.md#adr-43-codeql-a-ruleset-on-main-and-signed-release-assets)).
- [ADR-45](docs/decisions.md#adr-45-mask_uri-shows-option-values-from-an-allow-list) clarifies ADR-15: `mask_uri` shows option values from an allow-list of twelve keys, it does not look for secret-looking keys.
- `.github/workflows/scorecard.yml`: the OpenSSF Scorecard on a push to `main`, weekly and when branch protection changes; the score is published to scorecard.dev (README badge) and the SARIF report goes to code scanning. Permissions `{}` at the top, actions pinned to SHAs.
- `.github/dependabot.yml` (uv and github-actions, `open-pull-requests-limit: 0`): Dependabot is limited to security updates. After the first push GitHub's dependency graph still listed nothing from `uv.lock`; after the next push (with `requirements.txt`) a Dependabot `update-uv-graph` job ran and the graph lists the 76 locked packages (checked 2026-10-17). `docs/dependencies.md` says what was and was not tested.

### Changed

- The mutation gate (`make mutate-gate`, `scripts/mutation_gate.py`) now fails below a score of 95 instead of 90. The last full run scored 98.4% (13,027 killed, 206 survived), so the new floor leaves room for about 450 survivors; `CONTRIBUTING.md`, the README, `docs/quality.md`, `docs/assurance-case.md`, `CLAUDE.md`, `AGENTS.md` and the hosted `mutation.yml` say 95.
- `docs/ui.md` is split: it keeps the overview (how the frontend is built, the pages, the boot data) and links to one file per page or topic under `docs/ui/` (`shell`, `library`, `editor`, `viewer`, `settings`, `testids`, `testing`, `frontend`). Anchors moved with their sections; `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`, `docs/e2e.md`, `docs/api.md` and `qodana.yaml` point at the new files (the `data-testid` contract is now `docs/ui/testids.md`). Comments in `src` and `tests` that cited `UI.md` or `API.md section N` (files and numbers that no longer exist) now name the current `docs/ui/` part or `docs/api.md` section.
- `codeql.yml` also runs on pull requests to `main` (with its own concurrency group), so the OpenSSF Scorecard SAST check finds an analysis on each merged pull request; findings still go to code scanning and nothing requires the job ([ADR-43](docs/decisions.md#adr-43-codeql-a-ruleset-on-main-and-signed-release-assets)).
- The graph timing tests measure CPU seconds (`time.process_time()`), so a loaded machine no longer fails them, and the worst-case bound is wider.
- The two nested-JSON tests no longer depend on the stack limit of the machine: the first hosted CI run found that a host with a larger stack (a GitHub runner) decodes a 100000-deep document instead of refusing it. They now run the decoder in a thread with a 1 MiB stack, which makes the guard fire everywhere; the worst case on a big-stack host is bounded by the 1 MiB value cap (docs/assurance-case.md, T13).
- The docs no longer call `release.yml` the only workflow or say that there is no hosted CI: ten workflows and one local action exist (release, weekly Trivy, Scorecard, CodeQL, the hosted `ci`, `ci-e2e`, `ci-security` and on-demand `mutation`, and the two ClusterFuzzLite ones), nothing requires any of them to pass, and the ones that run on `pull_request` are `ci`, `ci-e2e`, `ci-security` and, for the code the fuzz targets read, `cflite_pr` (README, `docs/quality.md`, `docs/decisions.md`, `docs/dependencies.md`, `docs/assurance-case.md`, `docs/secrets.md`, `docs/release.md`, `SECURITY.md`, `CLAUDE.md`, `AGENTS.md`).
- `docs/quality.md` and `CONTRIBUTING.md` no longer say Trivy checks every dependency and every licence: it scans the runtime packages of `uv.lock` and cannot detect licences there. `SECURITY.md` no longer calls the project a one-person project.
- `SECURITY.md` lists the supported versions after 0.1.0 (latest release and `main`) and says how a release stops being supported. `MAINTAINERS.md` and `GOVERNANCE.md` no longer say the co-owner already approves releases or owns the PyPI project.
- Connection strings (the MongoDB URIs with their passwords) are now stored in `<data-dir>/credentials.json` (version 1, mode 0600, written atomically before `settings.json`), apart from `settings.json`, which holds no secret any more. The Settings page works as before; replacing `credentials.json` by hand applies on the next request, without a restart. A `settings.json` from an earlier version keeps working and is migrated by the next save; downgrading afterwards is not supported (the older version moves the new `settings.json` aside). A corrupt `settings.json` is now moved aside together with `credentials.json` (`.corrupt-<n>` pair); an unusable `credentials.json` is reported (422 `settings_error`, no value in the message) and left in place; one that group or others can read is tightened to 0600 on load ([ADR-46](docs/decisions.md#adr-46-connection-strings-live-in-credentialsjson), [docs/secrets.md](docs/secrets.md#the-credentials-file)).
- `--sources-dir` must not equal or contain `credentials.json` either (the error message lists it); `.gitignore` lists `credentials.json` and the `.corrupt-*` copies.
- `docs/secrets.md`, `docs/architecture.md`, `docs/assurance-case.md`, `docs/ui/testing.md`, the README, `CLAUDE.md` and `AGENTS.md` say where the strings live.

### Fixed

- The JSON reader treated a first read that held only the byte order mark as the end of the input, so the document read as empty. With the production chunk of 65,536 characters this needs a document that is exactly one BOM, so no real input was affected; the first ClusterFuzzLite run on a pull request found it with a chunk size of 1 (the `json_stream` differential target). The crash input is now a seed (`tests/fuzz/corpus/json_stream/bom_alone_in_chunk.txt`) and a unit test covers it.

## [0.1.0] - 2026-10-17

First release.

### Added

- README: the OpenSSF Best Practices badge (bestpractices.dev project 15611) under the title.
- Packaging for PyPI as `sankey-studio`: Trove classifiers, keywords and `project.urls` in `pyproject.toml`; the sdist holds only `src/`, the Markdown docs and the policy files (it was 6.3 MB with tests, `.claude/` and the hooks, now 0.7 MB); the README uses absolute image and document links so the PyPI page renders, and has an "Install from PyPI" section. `.github/workflows/release.yml` builds and checks the files on a `v*` tag and uploads them to TestPyPI and, after an approval, PyPI with trusted publishing (no token; actions pinned to SHAs); [docs/release.md](docs/release.md) and [ADR-39](docs/decisions.md#adr-39-releases-are-published-to-pypi-from-a-tag) describe the one-time setup and the steps.
- `GOVERNANCE.md` (roles, decisions, review, access rules), `MAINTAINERS.md` (the two organization owners) and `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1, reports go to the maintainers), linked from the README and `CONTRIBUTING.md`.
- `SECURITY.md` (supported versions, private reporting through GitHub private vulnerability reporting, response targets, scope) and `CONTRIBUTING.md` (reporting bugs, setup, the rules for code, tests and commits, license of contributions), linked from the README.
- License: Sankey Studio is released under the GNU General Public License, version 3 (`GPL-3.0-only`), copyright Giovanni Manzoni. The `LICENSE` file is the verbatim license text under one copyright line (so that GitHub recognises GPL-3.0), and, like Markdown and `docs/` images, it does not void the hook stamps; `pyproject.toml` carries the SPDX identifier, the license file and the author, and the README ends with a License section. Every Python, shell, JavaScript, CSS and template file under `src`, `tests` and `scripts` starts with a two-line SPDX header; `scripts/license_header.py` lists (and with `--apply` adds) missing headers and `tests/test_license_header.py` fails on a file without one ([docs/quality.md](docs/quality.md#test-conventions)). The build backend floor is `hatchling>=1.27`, the first release that reads a license expression.
- MongoDB runs on one server and on a cluster ([ADR-38](docs/decisions.md#adr-38-mongodb-runs-on-one-server-and-on-a-cluster)). The README lists the connection strings for a standalone server, a replica set, a `mongos` list and `mongodb+srv://`, and what the application sets itself (timeouts, pool); the Settings hint under a new connection string shows the same three shapes.
- `make e2e-mongo-rs` (marker `mongo_rs`): the real-MongoDB flows (sources, graph store, collections, write-back) and a topology test against a MongoDB replica set you run yourself, with `SANKEY_TEST_MONGO_RS_URI` from the environment or the repo-root `.env` (only that key is read). The database is the one in the URI path and must be empty; its collections are dropped at teardown. The release gate (pre-push of `main` and tags, `make gate-release`) runs it as the new `e2e-mongo-rs` check: no Docker, a missing URI is a skipped test and fails the check, an unreachable cluster fails the tests. The foreign-port guard of the real-MongoDB suite now judges a seed list member by member (a loopback member on 27017-27019 was not refused before).
- Settings, Storage: with "Files on this computer" chosen, the page prints the folder that holds the graph files ("Graphs folder: ...", test id `settings-storage-folder`). `GET /api/v1/settings` gains `bootstrap.graphs_dir` beside `bootstrap.sources_dir`.
- Git hooks run every quality check ([docs/quality.md](docs/quality.md#git-hooks), ADR-37). `pre-commit` and the new `pre-merge-commit` run `fast` (lint, typecheck, caps) on the tree about to be committed. The new `pre-push` checks the messages of the new commits with `commit-msg`, then runs, for each pushed ref that has no stamp yet, `fast`, `cov`, `memray` and `e2e`; a push whose remote ref is `refs/heads/main` or `refs/tags/*` also runs `security` (semgrep-test, semgrep, trivy), `e2e-mongo`, `qodana` and `mutation` (`mutate` then `mutate-gate`). The checks run one at a time, in the foreground, only on a clean working tree that is the pushed commit (otherwise the hook refuses first and says what to do). The logic is `scripts/githook_gate.py` and the `githook_*.py` modules next to it; the hook files are three-line shims.
- The replica-set secondary-read tests no longer race replication: the seed and the application's writes return only once every data-bearing member has them ([docs/e2e.md](docs/e2e.md#replica-set)).
- `make e2e` and `make e2e-serial` run in a network namespace of their own (`scripts/netns.sh`, loopback only): a docker interface of another project coming or going no longer aborts Chrome's requests with `net::ERR_NETWORK_CHANGED` and fails a test. Without `unshare` the suite runs in the host network as before ([docs/e2e.md](docs/e2e.md#how-to-run)).
- Preflight and inert files: the gate probes Docker, `QODANA_TOKEN` and the replica set (`make preflight-docker`, `preflight-qodana`, `preflight-rs`) before the first long check of a run, so a push of `main` that cannot pass is refused in seconds; and the stamp key is a digest of the tree without Markdown (outside `src/`) and images under `docs/`, so a README edit or a screenshot does not re-run `cov`, `e2e` and the rest.
- Stamps: a check that passed leaves `hook-stamps/<check>/<key>` in the git common directory (`security` also carries the UTC date), and the next commit or push of that tree skips it, so a failed or dropped push resumes where it stopped. A stamp is written only after every step exited 0, no test was skipped and the working tree did not change during the run. Every check of one run must also start on the tree that was verified for it (HEAD moved or a file saved between two checks stops the run), and a signal gives the whole process group of the running check up to 10 s to end before it is killed. The last run of each check is logged in `hook-logs/<check>.log`; one gate runs at a time (`hook-gate.lock`); every run prints and stores per-check durations, which measures the runtimes that are still unknown.
- The hooks fail closed: any skipped test fails a check (only the 8 mongo-marked unit tests may skip inside `cov`), a missing JUnit report, a cut-off report or a run with no test fails, a push that has to run `security` is refused while an `*_OFFLINE` variable is set, a missing `QODANA_TOKEN` fails `qodana`, and a dry run (`SANKEY_GATE_DRY_RUN=1`) exits 0 only when nothing would run and every new commit message passes `commit-msg`. Because a skip is a failure, `cov` needs Chrome or Chromium, `node`, `bash` and a Linux `/proc` on the machine. `git push --dry-run` (or `-n`) is recognised by `pre-push` and acts as a dry run: it prints the plan, runs no check and writes no stamp. An OS error on the stamp, log or lock files ends in one `gate: refusing: ...` line (the stamp directory is probed before a check starts), a busy lock or an offline switch says `commit refused: <check> did not run` and not `failed`, and a failing `make mongo-up` fails `e2e-mongo` at once instead of after the 60 s ping. Children run without git's local variables, `PYTEST_ADDOPTS` and `SANKEY_TEST_MONGO_URI`, with `UV_LOCKED=1`.
- `e2e-mongo` in the hooks starts the project Mongo with `make mongo-up` when `127.0.0.1:27117` does not answer and the new `make mongo-absent` confirms that Docker lists no project container (`scripts/mongo_wait.py` pings), sets `SANKEY_TEST_MONGO_URI` for that check only, and runs `make mongo-down` afterwards only when it started the Mongo itself; a container of yours that is still booting is waited for and left running.
- `make hooks-check` (verifies `core.hooksPath` and the modes of the four hook files) and `make gate-commit`, `make gate-push`, `make gate-main` and `make gate-release` (the same checks by hand for the tree of HEAD, for a person at a terminal); `make test`, `cov`, `memray`, `e2e` and `e2e-mongo` accept `JUNIT=<path>` and also write a JUnit report.
- Library collections: saved graphs can be grouped in a tree of collections (at most 8 levels and 1,000 collections; sibling names are unique ignoring case). `/?folder=<id>` opens one with a breadcrumb, the collections of that level and its graphs; a collection can be created, renamed, moved and deleted (deleting one moves its graphs and sub-collections up, nothing is deleted); a graph or a selection moves with "Move" or by dragging; a search looks in every collection and names the collection of each result; "New graph here" and `/graphs/new?folder=<id>` save a new graph inside one. In code the noun is `folder`.
- Library: drag a graph (or the picked graphs) or a collection onto a collection card or a breadcrumb link to move it, with no dialog: the same two moves as the Move dialog, the same refusals ("already here", "inside the collection being moved", "too deep (at most 8 levels)", plus "that collection no longer exists"), the same toasts and error handling, and the rules shared with the dialog in `folder-rules.js`. The Move buttons stay as the keyboard, screen reader and touch way. The text of an empty collection mentions both ways. Nothing is draggable on a read-only server or in a search or tag filter, text, buttons and checkboxes of a card are not drag handles (a click that wobbles still counts), and a drag that came from outside the page (a file, text, a link) is ignored. While dragging, the carried cards have `data-dragging` and the target under the pointer has `data-drop="ok"` or `"denied"` with `data-drop-reason` (a solid or a dashed outline, also in forced-colors mode; a refusal is announced as "Not possible: ..."). The breadcrumb links carry `data-folder-id` (`root` for Library). No new test id, no backend change.
- Collections API: `GET` and `POST /api/v1/folders`, `GET`, `PUT` and `DELETE /api/v1/folders/{id}`, `POST /api/v1/graphs/move`, `?folder=root|<id>` on `GET /api/v1/graphs` (not together with `q` or `tag`) and `?folder=<id>` on `POST /api/v1/graphs`; `folder_id` on graph definitions and summaries; the error codes `folder_rule` (422) and `folder_name_taken` (409); `folders` and `folder` in the library boot data, `folder_id` in the new-graph boot data.
- Collections are stored in `folders.json` next to the graph files, or in the MongoDB collection `sankey_studio_collections` beside `sankey_studio_graphs` (unique `(parent_id, name_key)` index); "Test storage" probes both, and a storage switch that copies the graphs copies the collections first (`folders` and `folders_skipped` in the copy report).
- Write-back: when the person agrees, an edit is written into the data and not only into the graph. A category typed on an entry or an added entry goes into pasted text, manual links, a managed text file (the existing file is replaced atomically) or a MongoDB collection (`find` with a plain equality filter: one `$set` or `$unset` on at most 1,000 documents chosen by `_id` and re-filtered, or one inserted document); a row reorder can go into text and files. Files and collections ask first ("Change your data too?"); the answer is saved with the graph in `source.write_back`, bound to a key the server builds from the resolved file, connection, database and collection, so another target asks again. "Keep in this graph" keeps one edit in the graph, "Keep in this graph, don't ask again" saves that choice.
- A node drag also rewrites the data in the default colour mode: the edit answers `pins` (hex colours) that keep every node or category colour, and the editor merges them into `style.node_colors` / `style.category_colors` with the new rows. `would_recolour` is now only the answer when the pins would not fit in the style.
- A `set_category` is no longer refused as `unsafe_value` because a node name starts like a formula; an added entry for a file or collection is not blocked by a full list of graph-only entries; a MongoDB category update of up to 1,000 long string `_id`s is no longer refused; a category field that equals or nests with the value field is `field_conflict`.
- `POST /api/v1/edits/plan` (pure, also open on a read-only server) and `POST /api/v1/edits/write` decide where an edit goes (`draft`, `file`, `mongo` or `graph`), say what the person must agree to and write it; 25 stable reasons explain why an edit stayed in the graph, with one fixed sentence each (formula-like text, system or `sankey_studio_*` collections, aggregate sources, no category field, more than 1,000 documents, a database user without write rights, ...).
- `--allow-source-writes` / `SANKEY_SOURCE_WRITES`: with `--allow-remote-writes`, a remote server may also write edits back to MongoDB sources (`--allow-remote-writes` alone does not); on loopback MongoDB write-back is always available. The remote banner prints `source writes: ENABLED|DISABLED`.
- A text rewriter (csv, tsv, SankeyMATIC, json and manual links) adds an entry, sets a category or reorders rows, keeps untouched lines byte for byte and writes only what the real parser reads back as the old data plus the intended change; JSON arrays are re-formatted (the dialog and a notice say so).
- Entries: "Add entry" opens a dialog (source, target, value, optional category) that adds a flow to the data (pasted text, manual links, a text file or a MongoDB collection) or, when it cannot or may not, to the graph only; it hints at new nodes and stays open with a plain sentence when the entry is refused.
- Entries: a "Graph-only edits (N)" chip lists the category edits, added entries and the custom node order that live in the graph and not in the data, with a Remove button on each; a notice says when category edits no longer match any entry.
- Entries: after the first category typed into data that had none, a toast "N other entries have no category." offers "Show them".
- Chart: click a bar of the Sankey to add a flow that starts at it (or ends at it when nothing leaves it) in the same "Add a flow" dialog, with a choice of direction.
- Chart: drag a bar to reorder the nodes of its column. The order is saved with the graph (`style.node_order`) and drawn by the viewer, compare and the SVG, PNG and HTML exports (Plotly `sort: "input"`); "Order nodes" is a dialog with Up and Down buttons for keyboard and single-pointer use, "Reset order" returns to the layout of the data. Rows of the data follow a drag only when that does not change any colour and the saved choice allows it.
- Editor: a gear next to the title opens a menu with "Edit details" (name, description and tags in a dialog) and "Change data source" (a guided switch between Text file, Paste, Upload, Manual and MongoDB that asks what to do with graph-only edits). Changing the source tab asks the same question.
- Editor: a two-step new-graph wizard (name, then data source) replaces the blank editor; "Do it later" starts an empty Paste or Manual graph; nothing is saved until Save.
- Editor: Style and Export open from a gear in the chart header, in a popover that keeps the chart live (Escape, a click outside or the close button closes it); the gear is marked when the server rejects a style value.
- Paste tab: clearing the data shows a "Cleared" toast with Undo.
- `POST /api/v1/preview` lists the drawn nodes (`nodes`, aligned with the figure labels); graph-only entries (`transform.extra_links`) and a stored node order are part of every graph build.
- End-to-end tests: page objects for the wizard, the graph menu, the details and change-source dialogs, the chart settings popover, the consent dialog and the collection library; shared HTTP scenarios for write-back and collections that also run against a real MongoDB; the `allow_source_writes` server option.
- Editor: pick the colour of "One colour" mode in the Colours section (`style.mono_color`), with a reset to the palette colour.
- Editor: tap a category's colour square in the chart's category table to open the colour picker; the pick is saved as the category colour (`style.category_colors`).
- Viewer: a display menu (an icon at the right of the chart tabs) with view-only switches for the value under the node names (Sankey) and the percentage and value on each donut slice; they start from the saved style, redraw at once, are sent as `node_values`, `donut_percent` and `donut_value` with `GET /graphs/{id}/render` and every export, and never change the saved graph.
- Editor: "Show values" for the donut (`style.donut.show_value`, off by default) prints the slice value under the percentage, in the order of the switches.
- Project scaffold managed with `uv`: `src/` layout, `sankey-studio` console script, dev dependency group.
- Shared domain contract: pydantic models for sources (text, MongoDB, manual), transforms, styles and saved graphs; columnar `SankeyGraph`; typed domain errors.
- Optional per-entry categories (from data, glob rules or explicit user choice) with a donut chart that shares the category colour map with the Sankey.
- Read-only MongoDB guard (`mongo_safety`), credential masking (`mask_uri`) and a cached `MongoClients` registry.
- SVG and PNG export for both charts (kaleido), plus HTML, JSON and CSV.
- Quality tooling: ruff, mypy (strict), pytest, pytest-memray memory budgets, 100% coverage gate, mutmut, Semgrep (custom rules + rule tests), Trivy, Qodana Ultimate Plus, GitNexus code-intelligence index.

- Text sources: csv, tsv, SankeyMATIC and JSON parsers with encoding/delimiter sniffing, per-row problem reporting (strict and lenient), size and record caps, and a hardened sources directory (upload, list, preview, delete) with symlink, traversal, case-collision and directory-lock protection.
- MongoDB sources: `find` and `aggregate` extraction under the read-only guard with row caps and time limits, BSON value normalisation (including UUID binaries), database/collection listing and field suggestions.
- Storage: file and MongoDB graph repositories, a local `settings.json` store with 0600 permissions and masked secrets, graph copy between stores with an unreadable-graph report, and export/import bundles.
- Graph building: merge/hide, minimum link value and top-N, cycle breaking, layering and category splitting with stable colour slots.
- Rendering: Sankey and donut figures with in-figure legends and escaped labels, a compare-view colour map, category and entry tables, HTML/JSON/CSV exports and SVG/PNG export behind size, pixel and time caps; memory-budget tests and a whole-pipeline memory profile script.
- Web interface served by `sankey-studio serve`: a library of saved graphs (search, tags, sorting, paging, import and export), an editor with a live preview (pasted, uploaded or managed text files, manual rows and MongoDB sources; transform and style options; an entries table to categorise links), a viewer, side-by-side compare and a settings page. Light and dark themes, full keyboard use, no external assets (Plotly is served locally).
- Browsers get an HTML "Page not found" or "Graph not found" page (404, same app shell, link back to the library) for unknown URLs, deleted or malformed graph links and invalid compare links; API paths and non-browser clients still get the JSON error.
- Settings: an "On this page" list beside the sections from 1280 px wide; a failed copy to a new storage location says how to switch without copying.
- Export panel: a "File colours" choice (Light, Dark, same as preview; default Light) used by every download, including images drawn by the browser.
- Upload tab: a styled "Choose a file" button instead of the browser's own file input.
- Stable hooks for browser tests: `data-ready` on charts, `data-loading` on the main area, and the test ids listed in `static/testids-extra.txt`.
- End-to-end tests: a live-server harness (mongomock, ephemeral ports), HTTP suites for settings, sources, categories, exports, library, MongoDB, storage switching, security and limits, and real-Chrome suites for the editor, library, compare, settings, dark mode, responsive layout and hostile text; `make e2e` runs them in five shards (about 90 s), `make e2e-mongo` runs the MongoDB flows against a real server when `SANKEY_TEST_MONGO_URI` is set.
- Project documentation: `README.md`, `CLAUDE.md`/`AGENTS.md` working agreement and `docs/` (architecture, API, UI, quality, end-to-end tests, decisions).

### Changed

- MongoDB failovers have their own messages: `NotPrimaryError` reads "has no primary right now; try again shortly", `AutoReconnect` and `NetworkTimeout` "was interrupted (<class>); try again shortly. A write in flight may have been applied", `WriteConcernError` and `WTimeoutError` "was not confirmed by enough members; it may have been applied". The statuses and the error classes do not change. The "Test connection" button of a saved connection pings with `primaryPreferred`, so a replica set that is electing a primary is not reported as unreachable while a secondary answers (testing a new or edited storage connection also creates indexes, which needs the primary). A write-back that the database refuses on update is worded "The database refused the change" (it said "the new document").
- Viewer: in the Donut tab the category table sits behind a link, like the links table under the Sankey: a closed "Table view of the categories" (`<details>`, new test id `category-details`) opens `category-table`, and stays open or closed when the chart is redrawn. The donut basis note stays above it. No backend change.

The gear is `export-menu-button` ("Export settings"), the popover is `export-menu-panel` (non-modal, hidden until opened; Escape, a press outside or focus leaving closes it; it stays open after a download); every other `export-*` test id is unchanged but now sits inside that panel. The chart card uses the full width of the page (the right-hand column and its 1100 px breakpoint are gone). Two new test ids, no backend change.

- `pre-commit` now runs lint, typecheck and caps (it ran only the code caps); `make sync` also enables the hooks (`make hooks`); `make e2e-mongo` runs two pytest processes (`-m "e2e and mongo"`, then `-m "mongo and not e2e"`).
- Working rules in `CLAUDE.md` and `AGENTS.md`: tests run only in the git hooks; agents run only the tests of their own change, never `--no-verify`, never `core.hooksPath`, never the heavy `make` targets, and push with `run_in_background`. `AGENTS.md` is in sync with `CLAUDE.md` again.
- Editor layout: the chart is a full-width row above Source and Transform (side by side from 900 px); the sticky chart pane and the "Go to the chart" link are gone; name, description and tags moved into the details dialog; Style and Export moved into the chart settings popover. An unsaved graph with a name shows `New graph: <name>` in the heading, and Save with an empty name opens the details dialog.
- `/graphs/new` starts with the wizard instead of a blank editor; a graph made from it is not saved yet (the leave prompt and "Not saved yet" apply) and a new graph no longer inherits a node order from the default style.
- The Clear button of the Paste tab is an icon inside the data box (top right) instead of a button under it.
- Graph bundles are version 2 and end with the collections of the exported graphs (version 1 files are no longer read); importing the same bundle again reuses a collection with the same name in the same place, and an import drops any saved write-back consent from its graphs (a consent names a file or connection of the exporting machine).

The Semgrep message of `sankey-no-mongo-writes` and the docs say so; the rule itself is unchanged and its waivers stay under `src/sankey_studio/storage/`.

### Fixed

- The MongoDB library stores (saved graphs and collections) read from the primary whatever `readPreference` the saved connection string carries. With `readPreference=secondary*` a save could not be loaded right away and a bundle import after a delete saw the deleted collections (found by the replica-set suite).
- A refused source write-back update (a collection validator, a shard key that may not change) is the answer `write_rejected` and the edit stays in the graph, like a refused insert; it was a 502 `source_write_failed`. An update of several documents is not atomic, so the documents before the refused one may already be changed.
- Viewer and editor: the Sankey no longer shows its legend twice (a legend row above the plot and the legend list under the chart). The row above the plot is gone from both pages and the plot uses the space; the legend list stays. Exports, the compare cards and the donut keep their in-figure legend.
- The 8 mongo-marked unit tests were never run (they skip in `make cov` without `SANKEY_TEST_MONGO_URI` and `make e2e-mongo` did not select them); `make e2e-mongo` now runs them and the release gate of the hooks runs `make e2e-mongo`.
- The documentation said that `make ci` is `check` plus `security`; it also runs `e2e` (README, `CLAUDE.md`, `AGENTS.md`, `docs/quality.md`), and `CLAUDE.md` claimed that the hooks ran the full suite when only the code caps ran.
- Editor: a bar dropped back into the order of the rows is stored when the automatic layout had drawn another order (the drag is compared with the order drawn when the press began, not with the row order); the Undo of an added entry or a node drag undoes only its own edit, and a new Undo toast replaces the older one instead of keeping its Undo.
- A collection whose parent record is missing can be renamed again (the parent is healed to the top level) and takes part in the top-level name check; a `keep_ids` import moves the graphs and sub-collections of a refused collection to the nearest stored ancestor.
- A headerless csv or tsv text now reads its category from the fourth column (donut chart and "Auto (col 4)"), like source, target and value use columns 1 to 3; "This data has no category column" (`detect_category=false`) turns it off. A fourth column that is not a category (a note, a date) now yields categories, with the usual single warning for unusable cells.
- A category typed on one entry is written into the data (the Paste box, the Manual table, a text file or a MongoDB collection, after the question above) and not only into the chart, so the other entries keep their data categories instead of all showing "Uncategorized"; manual pairs of merged nodes are found.
- The chart tabs of the viewer no longer show a vertical scrollbar beside the Donut tab.
- Static files (`/static/*`) and `/static/vendor/plotly.min.js` now answer `Cache-Control: no-store` (no `ETag`, no `Last-Modified`, never a 304), and every page links its style sheets, scripts and icon under a version prefix (`/static/v-<digest>/css/layout.css`) that nested modules and script-loaded style sheets share, so a browser never keeps showing an old UI after a change, not even with copies it stored before; the active header link (Library, New graph, Settings) is drawn in the accent blue, and "New graph" is no longer always blue.
- Saving settings above 1 MiB is refused instead of making the next load fail.
- Page `limit` and `offset` are capped at 2**31-1 (no 503 on the MongoDB backend); graphs above the 32 MiB file cap are refused when saved.
- A CSV record spanning many lines is capped at 64 KiB; the 4096-character line limit counts after a BOM; decode errors name the real line.
- Lenient JSON loads skip non-object array entries with a warning; `save_stream` accepts any `IO[bytes]`.
- The MongoDB row cap counts usable rows; database listing uses `nameOnly`; field suggestions never offer `_id`.
- Export maps every browser-protocol error to a clean 502; `valuesuffix`/`valueformat` are escaped.
- Host check ignores letter case (`CaseInsensitiveTrustedHost`); the bound loopback address always answers its own `Host`.
- `serve` with a bare IPv6 `--host` and `--allow-remote` starts; `[::]` and `::ffff:0.0.0.0` count as wildcards.
- A `SANKEY_MONGO_URI` the settings refuse exits 2 at startup (reason only, never the URI); the banner example no longer lists a host twice.
- `PUT /settings` with the same rename again (previous name gone, new name stored) answers 200 and keeps the secret instead of 422; saving settings is serialised (`Services.settings_transaction`), so a rotated secret is never lost.
- Mongo inspection and the Mongo probe no longer need the sources directory; `POST /settings/storage/test` runs at most 4 probes at once, then answers 503 `busy`.
- Every name `GET /sources/files` lists can be previewed and deleted (newline names included); names with a backslash, which those routes refuse, are no longer listed.
- Read-only remote mode answers 403 before decoding the body on `PUT /settings` and the probes (`GuardedRoute` is shared by the graphs, settings and sources routers).
- `GET /graphs/export` builds the bundle one graph at a time and refuses at the 16 MiB cap without loading the rest; it measures and writes UTF-8 (no `\u` escapes), so any graph `POST /graphs` accepts can be exported and imported.
- Every HTML page is sent with `Cache-Control: no-store`, so Back and Forward never show a page rendered before a change.
- `/compare` without ids opens the empty compare page, and deleted graphs in a compare link show a "This graph is gone" card without failed requests.
- A graph whose name has no visible characters is called "Untitled graph" in headings, titles, cards, menus, dialogs and toasts; such search text and tags no longer leave empty labels.
- Control characters (bell, escape, DEL, C1) in node, category and graph names no longer make SVG exports ill-formed or PNG exports fail; markup in names is drawn as literal text. The empty-basis donut hides its axes.
- A far-out `?page=` in the library address opens the last page instead of an error; export toasts use thousands separators; the chart toolbar can no longer offer "Share chart...".
- Settings: a theme change and Save settings no longer overwrite each other, in either order, even on a slow server; deleting or editing a connection cancels its running test (no stale toast, Save no longer waits behind dead tests); the "Holds your graphs" badge only shows while MongoDB is the storage; the System theme card names what the device does now; read-only servers no longer say connection strings can be replaced and show the copy box unticked; dismissing the copy report moves focus to Test storage.
- Editor: reverting an edit (clearing a field, putting a value back) no longer leaves "Unsaved changes" or the leave prompt; Paste rows keeps the first row of data with comma decimals and says when a header row was skipped; Save and Ctrl+S with an empty name mark the Name field even when it has focus; toggling "first row is a header" re-matches the columns; the paste counter counts an emoji as one character.
- A graph with no drawable links (empty data, every row skipped, or Transform filtering everything) shows a clear empty state instead of "The chart could not be drawn", with its exports disabled.
- The entries table refreshes after the server comes back (chart Try again), its notice has its own Try again, and a download the browser cannot draw says so instead of "Cannot reach the server".
- Library, viewer and compare reload after Back/Forward and cache restores without leaking chart observers; a failed import after Esc shows a toast; focus returns to Import and after compare removal.
- Page shell: the saved theme is rendered on first paint (no flash); header and banners reach the scrollbar; aborted requests, long text, focus under the sticky bar and the squashed toast close button are fixed; the editor's unsaved-changes flag compares with the last saved state; a refused save no longer marks the chart as out of date.
- Long chart titles in the editor preview wrap instead of being cut off at the edge.
- "Try again" on the entries notice also clears the chart's "server cannot be reached" message.
- The entries table no longer scrolls inside its own box; the page scrolls and the header row stays visible.
- A unit suffix such as `<b>$` is shown as typed in the viewer's totals instead of its escaped form.
- A MongoDB source no longer warns "Result truncated at limit N" when the collection holds exactly N documents: the server is asked for one document more than `limit`, and only that extra document (never turned into a row) makes the warning appear.
- A browser opening a page while the graph store is unreachable (503), or hitting any other server error, gets an HTML error page in the app shell instead of the raw JSON envelope; API clients are unchanged.
- The 422 for an unknown `source.type` no longer quotes the submitted value; it lists the allowed types.
- The editor's MongoDB tab pre-selects the only connection after "Check again", so its databases and collections load without picking it again.

### Security

- Category rules are bounded to 20 million (name x rule) matches per build, so a hostile settings file cannot stall a build.
- The MongoDB result-cache key includes a SHA-256 digest of the full connection string, so rotating only a password no longer serves a graph loaded with the old credentials for up to 30 s.
- Tests assert that log records (message, args, traceback), not only response bodies, never contain a MongoDB password.
- Names of nodes, categories and graphs are drawn as literal text in charts, hover text, legends and SVG, PNG and HTML exports: control characters and direction overrides are removed and markup such as `<a>` or `<b>` is escaped. Names with direction overrides can no longer reverse nearby text in the pages.
